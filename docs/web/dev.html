Architecture runtime

Tablette / navigateur
    │
    ▼
Nginx (sedi-tablette-frontend)  :80 / :443 / :8080
    │  /          → SPA frontend/
    │  /docs/     → docs/web/ (statique)
    │  /api/*     → proxy → backend:3001
    ▼
Express (sedi-tablette-backend)  :3001 (interne Docker)
    │
    ├── SQL Server SERVEURERP
    │     SEDI_APP_INDEPENDANTE  (app)
    │     SEDI_ERP               (ERP, vues SILOG)
    ├── CIFS /srv/services       (FSOP Excel, traçabilité)
    └── Redis (optionnel, cache)

Prod : docker/docker-compose.production.yml, projet sedi-tablette, réseau externe sedi-tablette-network. Le backend n'est pas exposé sur l'hôte — uniquement via Nginx.

Health : GET /api/health (backend), GET /health (Nginx). Métriques Prometheus : GET /metrics sur le backend.

Pipeline SILOG

  1. Opérateur stop → ligne dans ABHISTORIQUE_OPERATEURS, consolidation vers table temps ERP.
  2. Admin valide → StatutTraitement passe à O (visible via V_REMONTE_TEMPS).
  3. Job SILOG / EDI sur Windows (SVC_SILOG) : tâche planifiée toutes les 2 h.
  4. Marquage T (transmis) retire la ligne du dashboard admin.

Mode distant (SILOG_REMOTE_MODE)

ValeurComportement
scheduled (défaut prod) Pas de déclenchement SSH depuis le backend. Tâche planifiée Windows sur SVC_SILOG (toutes les 2 h).
autre (ex. direct) Backend peut appeler EdiJobService après validation batch.

Corps typique du transfert admin : 

POST /api/admin/monitoring/validate-and-transmit-batch
{
  "tempsIds": [376, 377],
  "triggerEdiJob": true,
  "adminMarkTransmitted": false
}

En mode scheduled, adminMarkTransmitted: true force le marquage T côté admin sans attendre l'EDI.

Docker & déploiement

Prod (serveurproduction)

cd /home/Tablette-FSOP/docker
cp .env.example .env   # si première fois, puis éditer
./deploy.sh

deploy.sh : down compose, rebuild images, up prod + monitoring, vérifie le réseau sedi-tablette-network.

Rebuild manuel

docker build -t docker-sedi-backend:latest -f docker/Dockerfile.backend .
docker build -t docker-sedi-frontend:latest -f docker/Dockerfile.frontend .
docker compose -p sedi-tablette -f docker/docker-compose.production.yml up -d

Doc statique

Dockerfile.frontend copie docs/web/ → /usr/share/nginx/html/docs/. Routes Nginx : /docs → redirect, /docs/ → fichiers statiques (docker/nginx.conf).

URLs après rebuild front : /docs/, /docs/dev.html.

Services systemd (hôte)

  • sedi-tablette.service — stack principale
  • sedi-backend-health.timer — sonde API
  • sedi-cifs-ensure.timer — montages partages FSOP
  • sedi-backup.timer — sauvegardes

Jenkins & Sonar

Serveur : http://192.168.1.26:8085

Pipeline (Jenkinsfile)

  1. Checkout
  2. Backend : npm ci + tests Vitest coverage
  3. Backend lint (non bloquant → unstable)
  4. Frontend : npm ci + tests + coverage Sonar
  5. SonarQube (sedi-sonar, projet tablette-fsop)
  6. Quality Gate (bloquant)
  7. Build images :test
  8. Deploy test (deploy-test.sh, branches main/master/feature/*)
  9. Smoke http://127.0.0.1:8088/api/health

Params : SKIP_SONAR, SKIP_DEPLOY. Sonar : http://192.168.1.26:9000

Tests locaux (même commandes que CI)

cd backend && npm ci && npm run test:vitest:run -- --coverage
cd frontend && npm ci && npm run test:run && npm run test:coverage:sonar

Terraform / Ansible

Phase 1 : inventaire uniquement (terraform/). Pas de création VM. Génère ansible/inventories/generated/fsop.yml. 

cd terraform
cp terraform.tfvars.example terraform.tfvars
terraform init -backend-config=backend.local.hcl
terraform apply

cd ../ansible
ansible-playbook -i inventories/generated/fsop.yml playbooks/silog-runner-prereqs.yml

Dev local

Backend

cd backend
cp .env.example .env   # ajuster DB_*
npm install
npm run dev            # nodemon, port 3033 si NODE_ENV=development

Frontend

cd frontend
npm install
npm run dev            # http-server :8080

Le front appelle l'API en relatif /api/... — en local, configurer un proxy ou pointer ApiService vers http://localhost:3001 / 3033.

Docker dev

docker compose -f docker/docker-compose.dev.yml up

Debug utile

  • GET /api/admin/silog-pipeline-status — état remontée
  • GET /api/admin/diagnostic-temps — anomalies temps
  • Routes /api/admin/debug/* — bloquées sauf ALLOW_DEBUG_ROUTES=true
